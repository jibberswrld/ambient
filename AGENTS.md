# Ambient — Agent Instructions

## Overview

Ambient is a macOS menu bar app forked from [Clicky](https://github.com/farzaa/clicky) under the MIT license. Preserve the original copyright in `LICENSE` alongside Ambient's copyright.

The app target links the local `Packages/AmbientKit` library. Its pipeline is Control+Option → temporary PCM WAV → `PublikSpeechClient.transcribe` → `AmbientAgentSession` with tools → memory learning and optional publik speech playback. The inherited vendor clients, Cloudflare Worker endpoints and pointing-tag parser have been removed.

The app imports `AmbientUI`. `AmbientAppDelegate` owns the live flow bar, settings, permissions, guided tour, status menu, shortcut and transient pointer. No inherited Clicky presentation remains.

## Architecture

- `AmbientRuntime` is the sole composition root, owning the credential source, session, completion/speech clients, background manager, memory/skill stores, connector and tool providers. Its settings-facing stores/services use contract protocol types.
- `AmbientRuntimeState` is the single observable conversation state: idle, listening(audioLevel), transcribing, thinking, working(activityLabel), responding(text), finished(finalText), failed(AgentFailure). The app forwards input phases and live microphone levels to `FlowBarModel`; session events reach the model directly through `onAgentEvent`. There is one agent pipeline.
- `AmbientInteraction` is the main-actor approval/authorization seam. Approvals await `FlowBarModel.requestApproval`, cancellation denies pending requests, and connector authorization opens the default browser. `PublikGateUI` presents `AmbientOnboardingWindowController`. Missing approval handlers deny by default.
- `Publik.ensureSignedIn` runs at launch. Ambient is listed on publik as `ambient` (https://publikhq.com/ambient). Its app token is `Ambient/publik-app-token.txt`, public by design, committed and bundled as a resource, so an ordinary launch provisions an install and shows Sign in with publik. `PUBLIK_API_KEY` in the environment still overrides it for development. Never persist development overrides. The launch script forwards `PUBLIK_API_KEY`, `PUBLIK_API_BASE_URL`, `AMBIENT_CONNECTOR_ORIGIN` through LaunchServices.
- `AmbientScreenToolProvider` supplies optional `look_at_screen`, `point_at` and `draw_on_screen` tools. `draw_on_screen` takes arrows, circles, boxes, lines, freeform paths (open or closed, optionally filled), underlines and captions, each in one of eight inks, in latest-capture pixels. It is used both to mark things on screen and to sketch shapes and diagrams stroke by stroke; captions are placed so they do not cover each other. It shows them with `AmbientAnnotationOverlayView`, drawn in order and numbered when several have captions. No screenshots accompany ordinary requests. Captures exclude Ambient windows and use a bounded JPEG budget. Pointing maps 1-based display indices and latest-capture pixel coordinates (top-left origin) to AppKit screen coordinates.
- `AmbientDictationManager` records 16 kHz mono PCM WAV and live levels, up to 90 seconds. It removes its own temporary recording after completion/cancellation.
- A new push-to-talk press or text submission cancels the turn and stops playback. A drawing is not cleared by a new request. `ambient.spokenRepliesEnabled` defaults to true. Replies are spoken sentence by sentence as they stream: each sentence is synthesized when it completes and played in order. With spoken replies on, the written reply is held back and revealed word by word while each sentence is being said (publik speech takes 1.2–2 s per sentence, far longer than the model takes to write it); a sentence that cannot be spoken is written at once. The voice is `tts-1` `coral` (Jabir found `ash` coarse) (`ambient.spokenVoice` overrides it); publik has no newer speech model. Successful turns start `MemoryStore.learn` in its own task, never ahead of the reply or its speech.
- The bar's conversation runs on `publik-smart` with `reasoning_effort` low. Measured on 2026-11-21 it is the quickest model publik serves to first token (about 1 s; `publik-fast` 1.1 s, `publik-balanced` 2–3.5 s), so there is no faster tier to switch to. Recordings are transcribed on this Mac by `AmbientLocalTranscriber` (Apple Speech, on-device only, about 0.3–0.5 s once warm) and fall back to publik `gpt-4o-mini-transcribe` (about 1.5 s) when on-device recognition is unavailable, not permitted, empty or slower than four seconds.
- `spawn_agent` starts Ambient's own agent unless the person asks for Codex or Claude Code by name. Ambient's agent (`BackgroundTaskManager.spawnInProcessAgent`) is a second `AmbientAgentSession` on the person's publik account with high reasoning effort. It has web search, connectors, memory, skills and `AgentWorkspaceToolProvider`: a zsh tool run under `sandbox-exec` that can write only in the agent's working directory, temp folders and a few caches. It has no screen access and cannot spawn. It cannot be resumed and does not survive a relaunch. `codex` and `claude` kinds run the person's own headless CLIs.
- Background task completions are logged, published as `latestBackgroundCompletion`, and available as independent `backgroundCompletions()` streams. Agent processes are headless; no Terminal/Codex window is opened. A finished agent's answer is its report: the tray row offers Read report, which opens Settings → Activity, where the report is shown as formatted markdown with Save as file and Copy, and the raw activity log one click away. Nothing opens on its own.
- `Packages/AmbientKit/Sources/AmbientContracts/Contracts.swift` is the subsystem agreement. Each subsystem depends only on that target. The app imports AmbientAgent, AmbientBackground, AmbientConnectors, AmbientMemory, AmbientContracts and AmbientUI.
- `connector/` contains the undeployed TypeScript service. Local default: `http://127.0.0.1:3019`. Its Composio key exists only in the service environment. Tool Router owns discovery, schemas, authorization and execution; do not add per-app adapters/catalogs. Read its README before changing it.
- `AmbientAnalytics.swift` and `windows/src-tauri/src/analytics.rs` send anonymous PostHog funnel events with a separate UUID and opt-out in `analytics.json` in each app’s data directory. Settings → General → Privacy controls it. Debug builds/tests send nothing unless `AMBIENT_ANALYTICS_DEV=1`; no account or request data enters these clients. Onboarding milestones are recorded once per install, and each submitted request ends with one command outcome, including cancellation. Publik’s existing usage counting remains separate.
- `AmbientSoundEffects` (AmbientUI) and its Windows twin play five quiet bundled WAV cues: listen (recording starts), send (a spoken or typed request reaches the agent; not the return to thinking after a tool), attention (an approval is shown), complete (the turn finishes and replies are not read aloud) and error (the turn fails, except cancellation). Background agents never sound. One volume constant per app (0.18; files peak at 0.5). Regenerate the files with `python3 scripts/make-sound-cues.py`, which writes both apps' copies. Settings → General → Sound effects, default on (`ambient.soundEffectsEnabled` on the Mac).
- Stores live under `~/Library/Application Support/Ambient/`. Never overwrite corrupt store files with empty data. The runtime reports initialization failures.
- `ambient://ask?text=...` is the permanent URL automation hook, routed through the same agent path and approvals. Before sign-in, the latest request is queued. Debug-only `--transcribe-wav` exercises the actual transcription path without a microphone.
- `NSLog` records local state, tool names, speech synthesis/playback and final background statuses. These logs contain conversation text; do not add credentials or raw tool payloads.
- `FlowBarPanelController` persists full placement with `FlowBarPlacementStore`. Settings receives the real connector, memory, skill and task stores. The Activity page can select the exact task requested from the tray.
- Settings persists spoken replies, background approval and shortcut choice. Login registration uses `SMAppService.mainApp` only when explicitly switched on, off by default. `GET /wallet` supplies optional handle, plan label and percentage remaining; no currency amounts or inferred allowance appear.
- Onboarding is the sign-in gate and a permissions step in `AmbientOnboardingWindowController`. It checks microphone, accessibility and screen recording (required) and speech recognition (optional; without it transcription falls back to publik) live and exposes system grant actions. Then the window closes and the guided tour teaches Ambient on the real desktop with the real bar: `AmbientTourModel` is a pure state machine the app feeds with real events (shortcut holds, runtime phases, agent events, approvals, dock edge, connected apps, permissions), and `AmbientTourPanelController` shows its coach card in a non-activating panel in the corner away from the bar. The panel is an ordinary window sized to the card (measured with `onGeometryChange`), one level above the bar, always taking clicks and dragged by its background; do not reintroduce click-through toggling there. Lessons: talk, show it your screen, hand off a job, connect apps (optional), place the bar; each completes only when it really happens. Completion uses `ambient.onboardingCompleted`, set when the tour finishes or is ended. Revoked required permissions reopen the permissions step.
- `AmbientPointerWindowController` creates a click-through transparent panel on the captured display for `point_at` (`AmbientPointerView`, removed after four seconds) or `draw_on_screen` (`AmbientAnnotationOverlayView`). The app keeps two: one for pointing and one for drawing. A drawing has no lifetime; it stays until the person removes it with the status menu's Clear Drawing, asks Ambient to (`clear_drawing` tool), or a new drawing replaces it. No cursor follower or welcome bubble exists.
- Sparkle 2 updates the app through publik. `Info.plist` points `SUFeedURL` at `https://publikhq.com/api/updates/ambient/appcast.xml`, which serves the `appcast.xml` asset of the published release; `SUPublicEDKey` is the public half of the EdDSA key kept in the login keychain under account `ambient` (and in the repo secret `SPARKLE_ED_PRIVATE_KEY`). `AmbientAppDelegate` starts `SPUStandardUpdaterController` before the runtime, so even an install that cannot start still updates. It checks at every launch (an explicit background check; Sparkle's own schedule is only daily), downloads in the background and asks before relaunching. The delegate's `SPUUpdaterDelegate` callbacks set `availableUpdateVersion` on the bar and settings models: the foot of the Settings sidebar always has Check for updates, which becomes an ember Update to <version> while one is waiting, and the bar's right-click menu item changes the same way. Sparkle compares `CFBundleVersion`, which follows `MARKETING_VERSION`.
- The template waveform status menu provides Open Settings, Show / Hide Bar, Replay the Tour, Clear Drawing, Check for Updates… and Quit Ambient. The bar's right-click menu also has Check for Updates…. Command-comma also opens Settings. Quit Ambient is also at the foot of the Settings sidebar and in the bar's right-click menu, because the status icon can be hidden behind the notch.

`AmbientTests/` covers permission routing, URL decoding and wallet mapping; `AmbientUITests/` retains inherited launch smoke tests. Run package and app tests after integration changes, and launch/interact with the signed app to verify actual behavior.

## Build & Run

```bash
./scripts/run.sh
```

Build with `scripts/run.sh`. It uses the shared `Ambient` scheme in `Ambient.xcodeproj`, Debug configuration, team `Z63L6KDQ9K`, and the **Developer ID Application** signing identity (the same one the released app uses). Derived data always goes to `build/`; the app is `build/Build/Products/Debug/Ambient.app`. `--build-only` verifies the signed build without launching. After a successful signed build it quits only this worktree’s running Ambient executable and launches the new app. It rejects an ad-hoc or wrong-team signature.

Use the same certificate/team, bundle ID (`com.jabir.ambient`) and app path between builds so macOS privacy grants can remain valid. macOS ties each grant to the signing requirement: a build signed with Apple Development takes Accessibility and Screen Recording away from the installed Developer ID app (the toggles stay on in System Settings, the app is refused, and the shortcut goes dead). If that happens, `tccutil reset Accessibility com.jabir.ambient` and `tccutil reset ScreenCapture com.jabir.ambient`, then grant again. Verify with `codesign -dv --verbose=4 build/Build/Products/Debug/Ambient.app`: it must report `TeamIdentifier=Z63L6KDQ9K` and a Developer ID Application authority. First use still needs microphone, accessibility and screen recording/content grants. Signing changes or OS policy may require granting access again.

Open `Ambient.xcodeproj` to inspect the project in Xcode. All configurations use macOS 14.2 and the same team. Test bundle IDs are `com.jabir.ambient.tests` and `com.jabir.ambient.uitests`.

Known inherited concurrency and deprecation warnings are non-blocking; do not fix them as part of shell/integration work.

## Code Style & Conventions

### Variable and Method Naming

IMPORTANT: Follow these naming rules strictly. Clarity is the top priority.

- Be as clear and specific with variable and method names as possible
- **Optimize for clarity over concision.** A developer with zero context on the codebase should immediately understand what a variable or method does just from reading its name
- Use longer names when it improves clarity. Do NOT use single-character variable names
- Example: use `originalQuestionLastAnsweredDate` instead of `originalAnswered`
- When passing props or arguments to functions, keep the same names as the original variable. Do not shorten or abbreviate parameter names. If you have `currentCardData`, pass it as `currentCardData`, not `card` or `cardData`

### Code Clarity

- **Clear is better than clever.** Do not write functionality in fewer lines if it makes the code harder to understand
- Write more lines of code if additional lines improve readability and comprehension
- Make things so clear that someone with zero context would completely understand the variable names, method names, what things do, and why they exist
- When a variable or method name alone cannot fully explain something, add a comment explaining what is happening and why

### Swift/SwiftUI Conventions

- Use SwiftUI for all UI unless a feature is only supported in AppKit (e.g., `NSPanel` for floating windows)
- All UI state updates must be on `@MainActor`
- Use async/await for all asynchronous operations
- Comments should explain "why" not just "what", especially for non-obvious AppKit bridging
- AppKit `NSPanel`/`NSWindow` bridged into SwiftUI via `NSHostingView`
- All buttons must show a pointer cursor on hover
- For any interactive element, explicitly think through its hover behavior (cursor, visual feedback, and whether hover should communicate clickability)

### Do NOT

- Do not add features, refactor code, or make "improvements" beyond what was asked
- Do not add docstrings, comments, or type annotations to code you did not change
- Do not try to fix the known non-blocking warnings (Swift 6 concurrency, deprecated onChange)

## Git Workflow

Use a task-specific worktree and feature branch. Do not modify sibling worktrees or the main checkout. Make concise imperative commits. Never commit credentials or generated `build/` output; never bypass hooks. Keep this document accurate when architecture or build instructions change.

## publik API
- Base URL: https://publikhq.com/api/v1 (OpenAI Chat Completions, Responses, Anthropic Messages)
- Models: publik-fast, publik-balanced, publik-smart or a vendor/model name from GET /models; never a bare model name
- Sign in with publik: the publik module's gate runs at start-up, before the first screen; it also sends usage telemetry
- Key: per-install `pk_` from POST /installs, stored at the publik credential path; env PUBLIK_API_KEY / PUBLIK_API_BASE_URL override
- App token: Ambient/publik-app-token.txt (public by design, committed) or PUBLIK_APP_TOKEN
- Releases: bump `Publik.appVersion` and `MARKETING_VERSION` together, build Release signed with the Developer ID identity, notarize it through Xcode's signed-in account (`xcodebuild -exportArchive` with `destination: upload`, then `-exportNotarizedApp`), and attach only `Ambient-macos.dmg` (the stapled app plus an Applications shortcut, signed with Developer ID) to a GitHub release so the disk image is the download publik offers, together with its `appcast.xml`. Make the feed after the disk image is final, with Sparkle's tool from the resolved package (`build/SourcePackages/artifacts/sparkle/Sparkle/bin`): put only `Ambient-macos.dmg` in an empty folder, run `generate_appcast --account ambient --download-url-prefix "https://github.com/jibberswrld/ambient/releases/download/<tag>/" <folder>`, and upload `<folder>/appcast.xml` to the same release. Upload both before publik scans the release; publik picks it up and scans it. Check with `curl -s -o /dev/null -w '%{http_code}\n' https://publikhq.com/api/updates/ambient/appcast.xml` (200 once the release with a feed is the published version). To stop a bad update, delete its `appcast.xml` from the release and ship a higher version; never reuse a version number. Never print, log or commit the private key. The disk image itself is not notarized: that needs a `notarytool` credential nobody has stored yet. The app icon is `Ambient/Assets.xcassets/AppIcon.appiconset`; each PNG must be exactly the pixel size its slot declares or the build ships with no icon.

## Windows version (`windows/`)

Ambient for Windows is a Tauri 2 app: a Rust core and a React interface. It is a port, not a fork: the Mac code is the source of truth for behaviour, prompts, tool names and schemas, and a change to one should be mirrored in the other.

- `windows/crates/` mirrors `Packages/AmbientKit`: `ambient-contracts` (the port of `Contracts.swift`; its header lists the Swift → Rust conventions), `ambient-agent` (publik sign-in from publik's official Rust module, the streaming model client, session, speech, web search), `ambient-background`, `ambient-connectors`, `ambient-memory`, and `ambient-platform` (what lives in the Mac app target: the hold-to-talk keyboard hook, microphone recording, playback, screen capture). Every crate depends only on `ambient-contracts`.
- `windows/src-tauri/` is the shell: `core.rs` is `AmbientRuntime` + `AmbientInteraction` (the one agent pipeline, approvals, the sign-in gate), `screen_tools.rs` is `AmbientScreenToolProvider`, `commands.rs` implements the host contract, `windows.rs` creates the windows and the tray menu, `updates.rs` is the Tauri updater on publik's `latest.json` feed.
- `windows/src/` is the interface (Vite, React, TypeScript). One page serves five windows chosen by window label: `bar`, `settings`, `onboarding`, `tour`, `overlay`. It talks to Rust only through `windows/src/host/contract.ts`; a command or event added there must be implemented in `commands.rs`/`core.rs` with exactly that name and shape. `?window=gallery` in a browser (`pnpm dev`) shows every state against a mock host; `pnpm screenshots` captures it.
- Differences from the Mac, on purpose: shortcuts are Ctrl+Alt (default), Ctrl+Win, Ctrl+Shift; the only permission is the microphone; transcription always goes to publik (no on-device recognizer); shell commands are PowerShell; there is no AppleScript tool; the in-process agent's shell runs as a low-integrity process that can write only in its working directory and its own temp folder (the equivalent of `sandbox-exec`); `codex`/`claude` npm shims are launched as `node <script>` directly, never through `cmd.exe`, so multi-line prompts survive; Ambient's windows are excluded from capture with content protection; one overlay window serves both pointing and drawing.
- Data: `%APPDATA%\Ambient` (settings.json, stores, `ambient.log`). The publik credential is the shared `%LOCALAPPDATA%\publik\apps\ambient.json`. Run on a Mac for development, the port keeps its data in `~/Library/Application Support/Ambient Windows Dev` and shares the Mac's publik sign-in.
- Run it on a Mac: `cd windows && pnpm install && pnpm tauri dev`. The shortcut hook is Windows-only; use the bar's text box or `ambient://ask?text=...` as the first argument. Spoken replies play through the speakers.
- Checks: `cargo test --workspace` and `pnpm typecheck && pnpm test` in `windows/`. Nobody here has a Windows machine: `.github/workflows/windows.yml` runs the tests on `windows-latest`, builds the NSIS installer (artifact `Ambient-windows-installer`), and runs the built app against `windows/ci/mock-publik.mjs`, keeping a desktop screenshot and the app's log as the `windows-evidence` artifact. A Windows-only change is not verified until that run is green and the evidence has been looked at.
- Releases: the version is `[workspace.package] version` in `windows/Cargo.toml` and `version` in `windows/package.json`; keep both equal to the Mac's. `.github/workflows/windows-release.yml` (run by hand with a tag whose version matches) builds the signed installer, scans it with Defender, and uploads it, its `.sig` and `latest.json` to that GitHub release (which can still be a draft: push the tag, make the release a draft, add the Mac files, run the workflow, then publish, so publik never scans a half-filled release), next to the Mac's `Ambient-macos.dmg` and `appcast.xml`. The update key is the repository secrets `PUBLIK_UPDATE_KEY` / `PUBLIK_UPDATE_KEY_PASSWORD` (also in the login keychain as "Ambient Windows update key"); its public half is in `tauri.conf.json`. The installer is not Authenticode-signed (no certificate exists), so SmartScreen warns when it is downloaded in a browser. The supported install is `irm https://raw.githubusercontent.com/jibberswrld/ambient/main/windows/install.ps1 | iex` (`windows/install.ps1`): PowerShell downloads carry no Mark of the Web, so SmartScreen does not run; Defender still scans. CI installs through that script and runs the app with Defender's real-time, behaviour and cloud protection on.
